# منصة محاضر مجلس الإدارة — عنان العاصمة للخدمات اللوجستية

منصة ويب لإعداد محضر اجتماع مجلس الإدارة بشكل جماعي:

- **كل مدير إدارة** يدخل بحسابه ويكتب ملخص تقرير إدارته + القرارات المقترحة (مع المسؤول والموعد النهائي) + الموضوعات المقترح تأجيلها.
- **سرية كاملة بين الإدارات**: المدير لا يرى إلا إدارته. الفصل مطبّق داخل قاعدة البيانات نفسها (Row Level Security)، وليس في الواجهة فقط.
- **الأدمن** يرى كل شيء: يُنشئ الاجتماعات، يتابع من سلّم ومن لم يسلّم، يعدّل أي إدارة، يقفل الاجتماع ويعتمده، ثم يطبع المحضر الرسمي أو يحفظه PDF بنفس قالب الشركة.
- **اعتماد القرارات**: كل قرار يقترحه مدير يكون «بانتظار الاعتماد». الأدمن يعتمده أو يرفضه (مع سبب). المعتمد فقط يدخل المحضر، ويُقفل على المدير. المرفوض يرجع للمدير بالسبب، ولو عدّله يرجع تلقائياً للمراجعة. الحماية دي مطبّقة داخل قاعدة البيانات (trigger) — المدير مستحيل يعتمد قراره بنفسه.
- **المرفقات**: كل مدير يرفق مع تقريره صور (PNG/JPG/WEBP/GIF) أو PDF أو Excel (XLSX/XLS/CSV) حتى 10 ميجا للملف. الملفات في مخزن خاص على Supabase Storage بنفس قواعد الفصل — المدير يرى ملفات إدارته فقط، والأدمن يرى الكل. أسماء المرفقات تظهر في المحضر تحت ملخص كل إدارة.
- بعد **قفل الاجتماع** لا يستطيع المديرون التعديل.

## دورة العمل

1. الأدمن يُنشئ الاجتماع ويكتب بياناته (التاريخ، المكان، الحضور).
2. كل مدير يدخل ويكتب: ملخص إدارته + قراراته المقترحة + الموضوعات المؤجلة + يرفق ملفاته، ويحفظ.
3. الأدمن يتابع من «متابعة الإدارات» مين سلّم ومين لسه.
4. الأدمن يراجع من «اعتماد القرارات»: اعتماد / رفض / إرجاع للمراجعة.
5. الأدمن يقفل الاجتماع ← يفتح «المحضر الرسمي» ← طباعة أو PDF.

## الهيكل

```
index.html            الصفحة الرئيسية
css/styles.css        التصميم + قالب الطباعة A4
js/config.js          إعدادات Supabase (فارغة = وضع تجريبي)
js/api.js             طبقة البيانات (Supabase أو تخزين محلي)
js/app.js             الواجهة
supabase/schema.sql   قاعدة البيانات وسياسات الصلاحيات
assets/logo.png       شعار الشركة
```

لا يحتاج أي build أو npm — ملفات ثابتة تُرفع كما هي.

## 1) تجربة سريعة (وضع تجريبي)

افتح `index.html` في المتصفح، واختر أي حساب تجريبي (أدمن أو مدير إدارة). البيانات تُحفظ في المتصفح فقط.

## 2) ربط قاعدة البيانات (Supabase — مجاني)

1. أنشئ مشروعاً على <https://supabase.com>.
2. من **SQL Editor** الصق محتوى `supabase/schema.sql` واضغط **Run**. (ده بيعمل الجداول + مخزن الملفات `attachments` + كل الصلاحيات.)
3. من **Authentication → Sign In / Providers** أوقف **Allow new users to sign up** (الحسابات يُنشئها الأدمن فقط).
4. من **Authentication → Users → Add user** أنشئ حسابك وحساب كل مدير (بريد + كلمة مرور، وفعّل Auto Confirm).
5. اجعل نفسك أدمن من SQL Editor:
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```
6. من **Project Settings → API** انسخ `Project URL` و `anon public key` وضعهما في `js/config.js`.
7. ادخل المنصة كأدمن ← **المستخدمون والصلاحيات** ← عيّن لكل مدير إدارته.

> مفتاح `anon` عام بطبيعته ومحمي بسياسات RLS، فلا مشكلة في رفعه. **لا تضع أبداً مفتاح `service_role`.**

## 3) النشر على GitHub Pages

1. ارفع المجلد على مستودع GitHub.
2. **Settings → Pages → Build and deployment**: Source = *Deploy from a branch*، Branch = `main` / root.
3. بعد دقيقة يصبح الرابط: `https://<username>.github.io/<repo>/`
4. في Supabase: **Authentication → URL Configuration** ضع رابط الموقع في **Site URL**.

## الإدارات

| المفتاح | الإدارة |
|---|---|
| `general` | الأداء العام للشركة |
| `operations` | إدارة التشغيل |
| `finance` | الإدارة المالية |
| `hr` | الموارد البشرية |
| `projects` | إدارة المشاريع |
| `fleet` | الأسطول والأصول |
| `development` | خطط التطوير والتوسع |

يمكن تعيين أكثر من إدارة لنفس الشخص (مثلاً الرئيس التنفيذي: الأداء العام + التطوير والتوسع).
